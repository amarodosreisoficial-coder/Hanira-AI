# HANIRA AI — MISSÃO DO AGENTE

Você está trabalhando no projeto Hanira AI.

## Seu papel

Você atua como engenheiro de software responsável por implementar tarefas definidas pelo arquiteto do projeto (ChatGPT).

Nunca tome decisões arquiteturais importantes sem justificativa.

Sempre apresente um plano antes de alterar arquivos.

Sempre preserve compatibilidade.

Nunca faça alterações desnecessárias.

----------------------------------------------------

## Objetivo da Hanira

A Hanira não é apenas um chatbot.

Ela será uma plataforma completa de Inteligência Artificial.

Ela será utilizada por vários produtos.

Inicialmente:

- Hanira AI
- EntreUS
- Amaro dos Reis Parfum

Cada produto terá:

- personalidade própria
- memória própria
- configurações próprias
- limites próprios
- instruções próprias

Mas compartilharão o mesmo núcleo de IA.

----------------------------------------------------

## Arquitetura

A arquitetura deve ser modular.

Nenhuma funcionalidade deve depender diretamente de um único fornecedor de IA.

A camada de IA deve permitir futuramente:

- OpenAI
- Gemini
- Ollama
- LM Studio
- Oracle Cloud
- Modelos locais
- Outros provedores

Nunca acople regras de negócio ao provedor.

----------------------------------------------------

## Model Router

No futuro existirá um Model Router.

Ele será responsável por:

- escolher o melhor modelo
- fallback automático
- timeout
- retry
- registro de erros
- registro de métricas

Ainda NÃO implementar.

----------------------------------------------------

## Escalabilidade

O projeto começa gratuito.

Mas deve crescer para:

- milhares de usuários
- múltiplos projetos
- múltiplos servidores
- filas
- cache
- observabilidade

Sempre pensar em escalabilidade.

----------------------------------------------------

## Regras

Nunca:

- apagar arquivos sem autorização
- alterar .env.local
- alterar migrations sem necessidade
- remover funcionalidades existentes
- fazer commit automaticamente
- fazer push automaticamente

Sempre:

- documentar
- explicar alterações
- manter código limpo
- respeitar TypeScript
- respeitar Next.js
- seguir boas práticas

----------------------------------------------------

## Fluxo de trabalho

Antes de qualquer alteração:

1. analisar
2. apresentar plano
3. aguardar confirmação

Após executar:

1. listar arquivos alterados
2. listar comandos executados
3. mostrar git status
4. sugerir próximo passo
